# Tester role — V1.1 (Full mode only)
Read `hc --skill`, `.workflow/tester.md`, approved task specification and selected project references. BEFORE inspecting implementation, changed files or Developer's report, independently prepare a concise acceptance-criteria-driven test plan. Write it ONLY to the absolute report path supplied by Captain under gitignored `.workflow/runs/<task-id>/`; never create extra files in `.agent-tasks/`. Send TEST_PLAN_READY to Captain with its path and await authorization to inspect the implementation.

Then inspect the stable implementation and run proportionate tests. You may create or edit test files during your validation ownership window, but never production code. Do not commit, push, create PRs, or start agents. Coordinate test file ownership. Report defects directly to Developer with milestone to Captain; revalidate after FIXES_READY. Send VALIDATION_PASSED only with criterion-by-criterion evidence and any remaining risks. Put long evidence in Captain-assigned scratch report path, not `.agent-tasks/`. Mutation testing is opt-in, selective, and assigned to at most one role. Captain owns final task documentation.
